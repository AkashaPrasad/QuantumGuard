# Components

## Vendored UI components (`src/components/ui/`)

All 29 files were generated by the shadcn CLI (`shadcn` 4.23.0, read from `node_modules/shadcn/package.json`) with `components.json` style `radix-lyra`, base colour `neutral`, icon library `lucide`. shadcn/ui is MIT licensed (`node_modules/shadcn/LICENSE.md`: "Copyright (c) 2023 shadcn"; source https://github.com/shadcn-ui/ui). They import `radix-ui` (MIT), `class-variance-authority` (Apache-2.0), `cmdk` (MIT), `cn` (MIT), `lucide-react` (ISC) and `recharts` (MIT).

Local changes were verified by reading the files. The `danger` variant in `button.tsx` is visible in the code. The title-size changes in `dialog.tsx` and `sheet.tsx` are as reported by the lead; the stock registry output is not on disk, so they cannot be diffed. The lead named three modified files (the brief said "four"). One other visible oddity, not provable as a change: `dialog.tsx` and `sheet.tsx` render the close icon as a multi-line `<XIcon />` with no props, which looks like formatter output from the CLI's icon transform.

## Custom components (written for this project, not copied from a registry)

Reasons come from `web/DESIGN.md` ("Custom components exist only where nothing fits") and code comments.

| Path | What it is | Why nothing off-the-shelf was used |
|---|---|---|
| `src/components/qg/toast.tsx` | Toast region and provider | Common toast libraries inject a `<style>` tag at run time, which the Content-Security-Policy (`style-src 'self'`) forbids (code comment). |
| `src/components/qg/receipt-slip.tsx` | A decision printed as a slip of paper: mono type, dashed rules, a "verified" stamp | The signature element in `DESIGN.md`: the stamp appears only after this device has checked the proof itself. No library component does this. |
| `src/components/qg/chips.tsx` | Status chips: a word with an icon on a tinted ground | `DESIGN.md`: meaning is never carried by colour alone; state words and icons follow the project's allow/deny/caution tokens. |
| `src/components/qg/error-notice.tsx` | The one way errors are shown: what happened, why, what to do, plus a details line with the code | Voice rule in `DESIGN.md`: say what happened, why, and what to do next. |
| `src/components/qg/ident.tsx` | Machine identifier (shortened, mono) with a copy button; relative time with exact UTC on hover | `DESIGN.md`: mono type for anything a machine produced; the copy button says what it copied. |
| `src/components/qg/page.tsx` | Page frame pieces: empty-state headline, table skeleton rows, key-figure block | Layout and empty-state rules in `DESIGN.md` (one serif headline, one sentence, the primary action; skeleton in final layout). |
| `src/components/qg/native-select.tsx` | A styled native select | Used instead of the registry Select, which renders a `<style>` element at run time that the Content-Security-Policy `style-src 'self'` blocks; a native control is also the most reliable picker on phones. |
| `src/lib/style-singleton.ts` | Replacement for the `react-style-singleton` module, aliased in `vite.config.ts` | The original inserts a `<style>` element for the dialog scroll lock; this applies the same CSS through a constructed stylesheet so the policy stays strict. |
| `src/motion/EncryptChunks.tsx` | Encryption drawn: blocks seal one by one as real chunk progress arrives | `DESIGN.md`: motion only where it explains a real event; driven by real progress, with a text equivalent for reduced motion. |
| `src/motion/KeyIssue.tsx` | Enrolment drawn: key pairs created, public halves sent, private halves locked in the device | Same rule; every stage is driven by a real event. Built on `motion`, which is a library, not a component. |
| `src/motion/MerkleClimb.tsx` | Verification as a climb from receipt to signed root | Each rung appears only when this device has finished that verification step; reduced motion lists the steps as text. |
| `src/motion/RevokeCut.tsx` | Revocation drawn: the line to the lost device is cut and key slots dissolve | Shown only after the revoke transaction has answered; explains a real event. |
| `src/motion/WrapBeams.tsx` | Wrapping drawn: one beam from the file key to each device | Completes when the server accepts each key slot; a checklist when motion is reduced. |
| `src/landing/Lattice.tsx` | Hero figure: slowly turning cubic lattice of points with one marked point | A 2D canvas, so no 3D library is shipped ("no 3D library is needed for seven hundred squares"). A single still frame when motion is reduced. |
| `src/landing/Landing.tsx`, `PublicLayout.tsx`, `Status.tsx`, `Docs.tsx`, `content.ts`, `links.ts` | Public site: landing page, frame, status page, API reference, copy, outbound links | Static, no third-party origins. `Docs.tsx` renders the API reference from the server's exported contract bundled at build time, so no documentation viewer is loaded from another origin. Links are set at build time. |
| `src/tour/Tour.tsx`, `steps.ts`, `tour.css` | Guided demo for operators; points and explains, the person does every click | Uses the `driver.js` library for positioning and highlighting; `tour.css` imports `driver.js/dist/driver.css` and restyles the popover to the project tokens (paper, hairline rule, `shadow-lift`, radius 0). Steps and role filtering are our own. |
| `src/app/` (`routes.tsx`, `guards.tsx`, `client-context.tsx`, `names.ts`, `nav.ts`, `theme.tsx`) | Routing, lock and revoked guards, client context, id-to-name lookup, navigation, theme | Application logic specific to the product; the public site and console are separate chunks (`routes.tsx` comment). |
| `src/app/shell/` (`AppShell.tsx`, `CommandPalette.tsx`, `PendingWorkBanner.tsx`, `StandalonePage.tsx`, `UnlockForm.tsx`, `useIdleLock.ts`, `Wordmark.tsx`) | Console shell: sidebar and top bar, command palette, background re-key banner, plain frame for enrol/unlock, idle lock, wordmark | Assembles shadcn primitives (`sidebar`, `command`) into the product's layout per `DESIGN.md`. `useIdleLock` locks the device after ten minutes without input. |
| `src/app/screens/` (20 screens plus `parts/`) | The console screens (Overview, Files, Devices, Evidence, Verify and others) | Product-specific screens composed from the components above. |
